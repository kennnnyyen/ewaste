# Prepare Recore content

1. Review recent entries in `app/blog-content.ts` and their images. Pick a distinct angle that answers a real customer question about retired IT, component recovery, secure data handling or collection. Write in Australian English and use a concrete example a Melbourne business can recognise.
2. Check technical, legal and environmental claims against authoritative sources where needed. Use Victorian government or EPA Victoria guidance for local rules. Describe possible recovery outcomes and qualify claims about value, collection and downstream processing. Verify Recore service details against the website.
3. Design an original feature illustration that communicates the article's central idea. Change the composition and subject from recent posts. For a process story, show the stages and plausible outputs. Add a second image when it teaches something distinct. Use approved Recore brand artwork when the brief calls for a logo. Supply descriptive alt text and check the homepage crop and article presentation.
4. Add the article using the existing blog data and route conventions. Save optimised WebP assets under `public/` with correct dimensions. Check the homepage card, article, canonical URL, sharing metadata and sitemap. Run the production build and provide the working local preview when asked to show the draft first.
5. When social copy is requested, adapt it to each channel. Give Facebook a reader-friendly hook and the article link. Give LinkedIn an operational takeaway for IT or facilities teams and the article link. Make Instagram image-led and point readers to the blog via the existing profile link or site navigation. Use a few relevant hashtags and retain the useful takeaway even when a reader stays in the feed.

Treat a draft or local review request as authorisation for preparation. When the user authorises publication, use the Recore publishing workflow for the approved material.
